# Predicting DDoS-Induced Server Downtime with a Transformer–BiLSTM Model

Code for the paper:

> **Toward Resilient Network Security: A Deep Learning Approach to Predicting DDoS-Induced Server Downtime**
> Md. Toufiqur Rahman, Ahsan Habib, Kumudu S. Munasinghe, and Md Farhad Hossain
> *29th International Conference on Computer and Information Technology (IEEE ICCIT 2026)*, Cox's Bazar, Bangladesh.

The model predicts, from five-minute windows of server and network monitoring data, whether DDoS attack traffic is driving a web server into downtime. It combines transformer-based self-attention with a bidirectional LSTM (the *attention-plus-bidirectional* design) and is evaluated on a dataset collected from a physical testbed under live attack.

---

## Dataset

The dataset is published on **IEEE DataPort** and is not stored in this repository:

> M. T. Rahman and M. F. Hossain, "Network Performance Monitoring Dataset under Benign and DDoS Attack Traffic," IEEE DataPort, 2026.
> **doi: [10.21227/pg53-f517](https://dx.doi.org/10.21227/pg53-f517)**

- **Testbed:** Apache2 web server on a Raspberry Pi (Ubuntu Server 22.04); traffic generated by two PCs; monitoring with PRTG Network Monitor.
- **Sessions:** 31 in total. 16 benign (legitimate TCP, UDP and HTTP traffic) and 15 attack (LOIC UDP flood that drove the server into downtime).
- **Readings:** 1,860 one-minute readings.

Download the dataset and place `merged_dataset.csv` in [`data/`](data/README.md).

## Installation

```bash
git clone https://github.com/Toufiq-Rahman/ddos-downtime-prediction.git
cd ddos-downtime-prediction
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Tested with Python 3.10–3.12, PyTorch 2.x and scikit-learn 1.3+. A CPU is sufficient: each experiment takes about 1–2 minutes on a laptop.

## Method summary

| Step | Setting |
|---|---|
| Input features (15) | CPU total + 4 cores, SNMP downtime, ping time, packet loss, HTTP loading time, total/in/out traffic volume and speed |
| Windowing | 5 consecutive one-minute readings, stride 3, within each session only; each window takes its session label |
| Proposed model | LayerNorm → multi-head self-attention (4 heads, key dim 15) + residual + LayerNorm → BiLSTM (32) → time-distributed Dense (32, ReLU) → Dense (15) → global average pooling → Dense (32, ReLU) → Dropout (0.5) → softmax |
| Training | Adam (lr 0.001), cross-entropy, batch size 32, up to 50 epochs, early stopping (patience 10) |
| Normalization | Standardization fitted on training windows only |
| Early stopping | On 3 validation sessions (2 benign, 1 attack) held out from the training folds |
| Repetitions | 5 folds × 3 seeds = 15 runs; mean ± std reported |

### Evaluation protocols

- **Window-level 5-fold CV:** windows are pooled and split at random, so windows of one session can appear in both training and test folds.
- **Session-independent 5-fold CV:** sessions are split into class-stratified folds, so all windows of a session stay in one fold. No session is used for both training and testing.

## Reproducing the results

```bash
# everything (about 6–8 minutes on a laptop CPU)
bash scripts/run_all.sh

# or individual experiments
python scripts/reproduce.py main  --protocol session                          # Table II
python scripts/reproduce.py main  --protocol window                           # window-level, Section V-B
python scripts/reproduce.py main  --protocol session --features no_downtime   # ablation, Section V-C
python scripts/reproduce.py extra --protocol session                          # 10 additional models, Section V-C
python scripts/reproduce.py pca   --protocol session                          # PCA study
```

Use `--seeds 0` for a quick single-seed run. Results are printed and saved to `results/`.

## Results

### Session-independent 5-fold CV (Table II of the paper)

| Model | Accuracy | Precision | Recall | F1-score |
|---|---|---|---|---|
| CNN (ResNet) | 0.844 ± 0.076 | 0.804 ± 0.187 | 0.718 ± 0.144 | 0.739 ± 0.112 |
| CNN-LSTM | 0.864 ± 0.063 | 0.853 ± 0.167 | 0.720 ± 0.113 | 0.766 ± 0.093 |
| BiLSTM | 0.872 ± 0.062 | 0.848 ± 0.156 | 0.748 ± 0.115 | 0.783 ± 0.097 |
| Transformer | 0.863 ± 0.078 | 0.842 ± 0.147 | 0.719 ± 0.232 | 0.739 ± 0.207 |
| **Proposed (Transformer–BiLSTM)** | **0.872 ± 0.071** | 0.801 ± 0.156 | **0.823 ± 0.134** | **0.798 ± 0.114** |

### Window-level 5-fold CV (same training procedure)

| Model | Accuracy | Precision | Recall | F1-score |
|---|---|---|---|---|
| CNN (ResNet) | 0.892 ± 0.044 | 0.851 ± 0.101 | 0.803 ± 0.099 | 0.818 ± 0.068 |
| CNN-LSTM | 0.889 ± 0.042 | 0.867 ± 0.070 | 0.753 ± 0.116 | 0.801 ± 0.080 |
| BiLSTM | 0.898 ± 0.039 | 0.872 ± 0.064 | 0.779 ± 0.105 | 0.819 ± 0.075 |
| Transformer | 0.912 ± 0.028 | 0.848 ± 0.062 | 0.871 ± 0.067 | 0.857 ± 0.045 |
| **Proposed (Transformer–BiLSTM)** | **0.914 ± 0.028** | 0.837 ± 0.059 | **0.897 ± 0.084** | **0.862 ± 0.046** |

Keeping sessions apart lowers accuracy by about 4–5 points (4.2 for the proposed model). Overlapping windows and session-specific patterns are no longer shared between training and test data, so the session-independent protocol is the better estimate for unseen sessions.

### Additional models (session-independent, Section V-C)

| Model | Accuracy | F1-score |
|---|---|---|
| LSTM | 0.836 | 0.704 |
| GRU | 0.863 | 0.774 |
| Two-layer BiLSTM | 0.872 | 0.779 |
| TCN | 0.856 | 0.755 |
| MLP | 0.865 | 0.758 |
| Random Forest | 0.827 | 0.751 |
| Extra Trees | 0.861 | 0.778 |
| Gradient Boosting | 0.822 | 0.722 |
| Logistic Regression | 0.831 | 0.782 |
| SVM (RBF) | 0.812 | 0.733 |

None of these exceeds 0.782 F1. The proposed attention-plus-bidirectional model achieves the highest F1-score (0.798) of all 15 models.

### Without the SNMP downtime feature (14 features, session-independent)

The proposed model reaches 0.861 accuracy and 0.783 F1, comparable to the Transformer (0.877 and 0.790). This shows the model does not depend on the downtime channel.

### Notes on reproducibility

- **Determinism:** results are deterministic for a given seed on CPU. Different hardware or library versions can change the last digit.
- **Table I and Table III:** these were obtained with the authors' original TensorFlow/Keras implementation on an earlier version of the session data, so this code does not reproduce them exactly. All other results in the paper (Table II, the window-level results in Section V-B, and the comparisons in Section V-C) are produced by this repository. Running the PCA study here (`reproduce.py pca`) gives the PCA results under this repository's protocol.
- **Parameter counts:** the counts in the paper are Keras parameter counts. PyTorch LSTM layers carry an extra bias vector, so `count_params.py` reports slightly higher numbers for the recurrent models.
